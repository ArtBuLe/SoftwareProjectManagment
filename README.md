Практическая работа №2. Создание концепции программного проекта

Шаблон концепции проекта

1. Название проекта
Разработка консольной игры «Тетрис» на языке C#.

2. Описание проблемы
У одногруппников и самого разработчика отсутствует простая консольная реализация классической игры «Тетрис», которая могла бы использоваться для коротких перерывов в учёбе, а также служить наглядным примером работы с игровым циклом, обработкой ввода и отрисовкой в консоли на языке C#. Существующие в интернете решения либо избыточны, либо написаны на других языках, либо не подходят для изучения основ программирования.

3. Целевая аудитория
Сам разработчик и одногруппники, использующие консольное приложение для отдыха между учебными задачами и для изучения примера реализации игры на C#.

4. Цель проекта
Разработать за 1 - 2 недели полноценную консольную версию игры «Тетрис» на языке C#, реализующую классические механики (падение фигур, очистка заполненных линий, подсчёт очков, ускорение падения), с возможностью сборки и запуска в консоли Windows.

5. Ожидаемый результат
Исполняемый файл (.exe) консольного приложения, исходный код на C# с реализованным игровым циклом, функционал: генерация и поворот фигур, управление с клавиатуры, отрисовка поля в консоли символами, подсчёт очков, система уровней с нарастающей сложностью, экран завершения игры (Game Over).

Представление результатов (ответы на вопросы для защиты)

1. Какую проблему решает ваш продукт?
Продукт решает задачу создания простой консольной игры для отдыха между учебными задачами, а также служит практическим примером реализации игровой логики на C# для изучения одногруппниками.

2. Кто будет им пользоваться?
Сам разработчик и одногруппники, запускающие консольное приложение в терминале Windows для игры или изучения исходного кода.

3. Что конкретно вы собираетесь разработать?
Консольное приложение на языке C#, содержащее классическую механику «Тетриса»: поле 10x20, 7 стандартных тетромино, отрисовку символами в консоли, систему очков, уровней и экран Game Over.

4. Какие специалисты нужны?
Функционально необходимы руководитель, аналитик, разработчик, тестировщик и заказчик, но все эти роли выполняет один человек — Булышев А.А.

5. Какие проблемы могут возникнуть при реализации?
Основные проблемы:
— мерцание экрана при перерисовке поля в консоли;
— сложность обработки ввода без блокировки игрового цикла;
— риск нехватки времени из-за совмещения всех ролей одним человеком;
— риск изменения требований (добавление лишних функций), из-за чего не удастся уложиться в 2 месяца. В таком случае будет жёстко фиксироваться объём работ, а новые идеи переноситься в версию 2.0.
