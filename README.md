Пересмотр распределения работ
1. Backend-разработчик: план сокращается до 20 часов. Приоритет №1 - исправление критических ошибок в БД. Приоритет №2 - предоставление четкого контракта API (список эндпоинтов и форматов данных).
2. Frontend-разработчик: план сокращается до 20 часов. Разработка интерфейса переключается на использование Mock API (имитация данных) на основе согласованного контракта, без ожидания реального бэкенда.
3. Тестировщик: план увеличивается до 15 часов. Написание тест-кейсов, ручное тестирование доступных модулей, помощь в подготовке пользовательской документации.
4. Дизайнер: план увеличивается до 10 часов. Финализация всех макетов, помощь тестировщику в визуальном оформлении инструкций.
5. Аналитик: остается 12 часов. Посредничество и фиксация контракта взаимодействия API между Frontend и Backend.

Решение руководителя проекта по разрешению конфликта
1. Главная проблема: блокировка работы Frontend-разработчика из-за зависимости от Backend и критическая перегрузка обоих разработчиков, ведущая к срыву сроков.
2. Фиксируемые договоренности: Frontend переходит на разработку с использованием Mock-данных. Backend фокусируется исключительно на исправлении БД и реализации согласованного контракта API. Любые изменения в структуре API замораживаются до релиза.
3. Ответственный за согласование API: Аналитик (или технический лид), который документирует и утверждает контракт взаимодействия.
4. Параллельные задачи: Frontend разрабатывает интерфейс с моковыми данными параллельно с тем, как Backend исправляет ошибки в БД. Тестировщик пишет тест-кейсы параллельно с разработкой.
5. Контроль выполнения: Введение ежедневных 15-минутных стендапов для отслеживания прогресса по исправлению БД и готовности моков. Обязательное обновление статусов задач в трекере в конце каждого рабочего дня.
