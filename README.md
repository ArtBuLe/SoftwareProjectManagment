**Практическая работа №2. Формирование команды проекта**

**Определение необходимых ролей**
| Роль | Основные обязанности | Возможность совмещения |
| - | - | - |
| Руководитель проекта | Планирование сроков, контроль этапов, управление рисками, приёмка результатов. | Совмещается с любой другой ролью в рамках данного проекта. |
| Системный аналитик | Сбор требований, проектирование архитектуры классов, выбор алгоритмов и структур данных. | Совмещается с ролью разработчика. |
| Разработчик | Написание кода на C#, реализация игровой логики, отрисовка в консоли, сборка приложения. | Является основной выполняемой ролью. |
| Тестировщик | Составление тест-кейсов, поиск багов, проверка коллизий, финальная приёмка продукта. | Совмещается с ролью разработчика (самотестирование). |

**Распределение участников**
Формальное разделение ролей необходимо для соблюдения методологии управления проектом, чёткого понимания этапов (анализ -> разработка -> тестирование) и предотвращения хаотичного написания кода без предварительного планирования.

**Определение полномочий**
| Роль | За какие результаты отвечает | Самостоятельные решения | Решения, требующие согласования |
| - | - | - | - |
| Руководитель проекта | Своевременная сдача проекта, соответствие целям устава. | Приоритезация задач, перенос сроков внутри общего дедлайна (1-2 недели). | Изменение финальной даты сдачи (согласование с преподавателем/дедлайном). |
| Системный аналитик | Качество архитектуры, читаемость и масштабируемость кода. | Выбор структур данных (массивы, списки), паттернов проектирования. | Кардинальное изменение механики игры, выходящее за рамки устава. |
| Разработчик | Работоспособный код, отсутствие синтаксических ошибок, сборка .exe. | Рефакторинг кода, выбор стилей форматирования, оптимизация циклов. | Добавление новых библиотек или изменение целевой платформы. |
| Тестировщик | Отсутствие критических багов, соответствие поведения игры ожидаемому. | Статус задачи "Не пройдено", требование переделать логику при обнаружении ошибок. | Принятие решения о выпуске версии с известными некритичными багами. |




**Практическая работа №3. Создание матрицы RACI**

**Выбранные работы проекта (адаптировано под консольный Тетрис)**
1. Сбор и фиксация требований к механикам.
2. Проектирование архитектуры классов (Поле, Фигура, GameLoop).
3. Реализация класса игрового поля (матрица 10x20).
4. Реализация логики фигур и их поворота.
5. Реализация системы коллизий (стены, дно, другие фигуры).
6. Реализация удаления заполненных линий и подсчёта очков.
7. Настройка консольного интерфейса и отрисовки без мерцания.
8. Реализация обработки ввода с клавиатуры в реальном времени.
9. Функциональное тестирование механик и поиск багов.
10. Финальная оптимизация и сборка исполняемого файла (.exe).

**Матрица ответственности RACI**
| Задача | Руководитель проекта | Системный аналитик | Разработчик | Тестировщик |
| - | - | - | - | - |
| 1. Сбор и фиксация требований | A | R | C | I |
| 2. Проектирование архитектуры классов | A | R | C | I |
| 3. Реализация класса игрового поля | A | C | R | I |
| 4. Реализация логики фигур и их поворота | A | C | R | I |
| 5. Реализация системы коллизий | A | C | R | I |
| 6. Реализация удаления линий и подсчёта очков | A | C | R | I |
| 7. Настройка консольного интерфейса и отрисовки | A | C | R | I |
| 8. Реализация обработки ввода с клавиатуры | A | C | R | I |
| 9. Функциональное тестирование механик | A | I | C | R |
| 10. Финальная оптимизация и сборка .exe | A | I | R | C |

Проверка матрицы:
- У каждой задачи есть минимум один исполнитель (R).
- У каждой задачи ровно один ответственный (A) — Руководитель проекта.
- Нет задач без ответственного.
- Все участники (Руководитель, Аналитик, Разработчик, Тестировщик) задействованы в проекте и имеют чёткие обязанности (R, C или I).
- Обязанности не противоречат друг другу: аналитик проектирует, разработчик реализует, тестировщик проверяет, руководитель контролирует итог. Несмотря на то, что все роли выполняет один человек, формальное разделение гарантирует, что этап тестирования не будет пропущен в угоду скорости написания кода.
