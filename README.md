| - | - | - | - | - | - | - |
| 1 | Государственная организация заказывает систему учёта документов. Требования заранее согласованы, изменения допускаются только через официальную процедуру согласования. Существует подробное техническое задание. | Waterfall | 1 - Подробное ТЗ и согласованные требования позволяют сразу и точно выполнить задачу | 2 - Госзаказ, согласованные требования и подробное ТЗ | 3 - четкая и понятная структура работы и ее документация | 4 - если обнаружится ошибка в требованиях или заказчик резко решит что-то добавить то внести изменения будет поздно, либо это будет стоить дорого и требовать тонну усилий |
| 2 | Команда создаёт мобильное приложение. Заказчик пока не знает, каким должен быть окончательный интерфейс. После каждой демонстрации он предлагает изменения и улучшения. | Agile | 1 - Позволяет гибко реагировать на изменения и постоянно получать обратную связь, так как конечный результат изначально не определён | 2 - Неопределённость интерфейса, активное участие заказчика, частые демонстрации и постоянные запросы на доработки | 3 - Быстрая адаптация к пожеланиям клиента, ранний выпуск рабочих прототипов, высокая вовлечённость заказчика в процесс | 4 - Риск бесконечного расширения функционала, сложности с точной оценкой итоговых сроков и бюджета, возможная усталость команды от постоянных правок |
| 3 | Необходимо создать интернет-магазин. Сначала требуется реализовать каталог, затем корзину, после этого оформление заказа и оплату. Каждая часть должна работать самостоятельно. | Инкрементальная | 1 - Позволяет создавать продукт постепенно, добавляя независимые функциональные части (инкременты), которые уже приносят пользу | 2 - Чёткое разделение системы на логические модули и требование их самостоятельной работы на каждом этапе | 3 - Возможность раньше выпустить работающую часть продукта, упрощение распределения задач, гибкая расстановка приоритетов | 4 - Необходимость тщательного предварительного проектирования архитектуры, сложность интеграции новых частей и тестирования их совместимости |
| 4 | Команда разрабатывает систему распознавания документов. На первом этапе создаётся простая версия алгоритма, затем команда проверяет точность, анализирует ошибки и несколько раз улучшает алгоритм. | Итерационная | 1 - Позволяет многократно проверять, анализировать и углублённо улучшать один и тот же компонент на основе полученных данных и метрик | 2 - Исследовательский характер задачи (алгоритм), необходимость проверки точности, анализа ошибок и цикличной доработки ядра системы | 3 - Раннее выявление слабых мест алгоритма, постепенное повышение качества продукта, снижение риска создания полностью нерабочего решения | 4 - Риск "застревания" на этапе доработок без чётких критериев остановки, возможное увеличение сроков, необходимость постоянной оценки результатов |
