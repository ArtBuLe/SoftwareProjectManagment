**Определение проблемы**
Какую проблему: Хаос с остатками товаров, пересорт и потеря времени на инвентаризацию.
У кого: У кладовщиков и владельцев малого бизнеса.
Почему существующий неудобен: Учет ведут в тетрадях или Excel, данные устаревают, файлы теряются.
Почему ПО поможет: Централизует данные, обновляет остатки в реальном времени, убирает человеческий фактор.

**Формирование цели проекта**
Разработать веб-приложение для автоматизации учета поступления, выдачи и контроля текущих остатков товаров на складе.

**Определение участников**
| Роль | Ответственность |
|---|---|
| Руководитель проекта | Контроль сроков и связь с заказчиком |
| Аналитик | Сбор требований и описание процессов |
| Разработчик | Написание кода и создание базы данных |
| Тестировщик | Поиск багов и проверка сценариев |

**Определение результата**
Веб-приложение для учета склада.
База данных товаров и операций.
Функция добавления и списания товаров.
Поиск по наименованию или артикулу.
Отчет по текущим остаткам.

**Определение ограничений**
Возможные проблемы: Непонимание требований заказчиком, болезни сотрудников, ошибки при переносе старых данных.
Ограничения: Срок 3 месяца, команда 4 человека, бюджет ограничен, платформа веб, результат работающий продукт.

**Оформление концепции**
1. SmartWarehouse
2. Учет товаров ведется в Excel, что приводит к ошибкам и пересорту.
3. Кладовщики, менеджеры, владельцы склада.
4. Создать веб-приложение для автоматизации учета поступления и выдачи товаров.
5. Работающее веб-приложение с базой данных, поиском и отчетами по остаткам.
6. Руководитель, аналитик, разработчик, тестировщик (обязанности указаны в таблице выше).
7. 3 месяца.
8. Бюджет ограничен, только веб-платформа, команда 4 человека.
9. Срыв сроков из-за сложных правок, потеря данных при миграции, нехватка времени на тестирование.

**Представление результатов**
1. Решает проблему хаоса с остатками и пересорта на складе.
2. Кладовщики, владельцы бизнеса, менеджеры.
3. Веб-приложение с базой данных для учета поступления и выдачи товаров.
4. Руководитель, аналитик, разработчик, тестировщик.
5. Непонимание требований, нехватка времени, ошибки при переносе данных.
