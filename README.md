**Практическая работа №1. Оценка рисков и составление реестра**

|R01|Задержка разработки ключевого функционала|4|5|20|Критический|Руководитель проекта|

**Три критических риска с наибольшим значением R:**
1. R01 - Задержка разработки ключевого функционала (R=20)
Почему опасен: напрямую угрожает срывом сроков сдачи проекта и невыполнением основных требований заказчика.
Какие задачи затрагивает: все последующие этапы - тестирование, внедрение, демонстрация заказчику.
Последствия без реагирования: проект не будет сдан в срок, потеря доверия заказчика, возможные финансовые санкции.

2. R07 - Недостаток времени на полноценное тестирование (R=16)
Почему опасен: приводит к выпуску продукта с критическими ошибками, которые обнаружатся у пользователей.
Какие задачи затрагивает: качество продукта, удовлетворенность пользователей, репутация команды.
Последствия без реагирования: выпуск нерабочего продукта, необходимость срочных исправлений после релиза, потеря доверия.

3. R03 - Недоступность внешнего API интеграции (R=15)
Почему опасен: блокирует работу функционала, зависящего от внешнего сервиса, делает систему неполноценной.
Какие задачи затрагивает: интеграция с внешними системами, демонстрация заказчику.
Последствия без реагирования: система не сможет выполнять заявленный функционал, невозможность демонстрации.
